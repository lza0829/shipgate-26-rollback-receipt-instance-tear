# 回退完成定义与残留收敛口径（唯一口径，全局面对齐）

本文件是回退（回滚）功能的完成口径真源。回退写口、发版单状态、名册版本、实例册行、
健康探针、对账、总览、审计八处必须认同一个完成定义，禁止各面自行解释。

## 1. 选型：严格收敛臂

两条候选路线中，本系统采用 **「以回退成功必须实例册收敛为准」**：

> 还有残留旧包实例就不得标 `已回滚`；名册与对账不得提前报成功，总览也不得计完成。

不采用「先标已回滚再挂残留账」臂。因此系统中**不允许出现** `已回滚` 与残留并存的状态，
也不允许出现名册已切旧版而实例册仍全挂新包的状态。

## 2. 唯一残留语义

- 残留是实例册行的属性，不是健康灯属性。全局只有一套残留标记：
  `instances.residual_release_id`（残留归属发版单）。非 NULL 即该发版单的回退残留行。
- 回退启动时，同应用、同当前环境内**版本不等于回退目标版本**的在册实例，全部打上该单的
  残留标记；目标版本实例确保在册且不挂残留标。
- 健康探针（探针绿/探针红）与残留正交：残留行可以是绿灯（旧进程心跳正常），绿灯不消除
  残留身份；红灯也不自动等于残留。禁止用心跳/探针对残留做默默抹平。
- 残留行只能通过**残留清理入口**删除，删除即写审计。普通探针对残留标只读不写。

## 3. 状态机（发版单侧）

```
已放行/晋升中 --回退写口--> 回滚中（名册不切，残留行挂账 + 退役标同落）
回滚中 --四源缺口清零（清理入口或启动时本就无残留）--> 已回滚（同事务：名册切目标版本 + 退役批次行 + 审计收敛）
回滚中 --再次回退写口（同目标）--> 幂等重放，仍为回滚中/已回滚，结局可重放；绝不改写回执状态
已回滚 --再次回退写口--> 幂等返回；携带不同目标版本一律 400
```

- `回滚中` 是唯一的「半截」状态，本身就是明示残留账：残留数与缺口数可在实例册、对账、总览核到。
- 名册（app_env_versions）只在四源缺口清零的收敛事务内翻转，因此
  「名册旧版 ⇔ 发版单已回滚 ⇔ 四源缺口为 0」三者恒同时成立。
- 回退写口幂等重放只做收敛判定，**不得把回滚中洗回已放行**、不得伪造 `回执.成功`/`surface_ok`。

### 2.1 退役标与四源同核（本事故收口口径）

残留标是「账」，退役标是「实」。只有账实同清才允许宣称干净，因此收敛判定不只认残留标：

- **退役标**：`instances.retired_by_release_id`（行级，谁退役了这行）+ 
  `releases.retired_at` / `releases.retired_version`（批次正式行，收敛事务内随 `已回滚` 同落）。
  回退启动时，同一批旧包实例同时落残留标与退役标；两标同命运，清理入口一并删除。
- **四源同核**：`已回滚` 的干净宣称必须同时满足
  ① 残留旁读为 0（`residual_release_id` 无本单行）；
  ② 实例册无本单在跑的旧版本行（版本 ≠ 回退目标仍挂账，退役标缺位也逃不出）；
  ③ 退役标无缺位（本单缺口行逐行有 `retired_by_release_id`）；
  ④ 批次对照一致（残留行与发版单同应用、同环境、版本 ≠ 回退目标，逐行对得上）；
  ⑤ 审计重放无矛盾（库内非 `已回滚` 时不得存在「回滚收敛完成」回执）。
- 判定收口在 `db.rollback_gap()` 单一函数，回退页、实例册、批次对照列、对账、总览、审计
  一律读它，禁止各面自造「干净」。
- **残留清零 ≠ 干净**：只清残留标而旧实例仍在跑时，`回滚中` 保持、`干净可宣称=false`，
  对账/总览以「缺口」而非「残留 0」判假干净。

## 4. 并发与重放

- 回退写口、残留清理、健康探针写口一律 `BEGIN IMMEDIATE` 起写事务，SQLite 库级串行化。
  回退与实例心跳并发时，每个事务提交后的结局确定、可重放，不依赖时序。
- 回退写口对同一发版单、同一目标版本幂等；残留清理重复调用不产生幻影行。

## 5. 八面对齐表

| 面 | 回滚中（有缺口） | 已回滚（四源缺口为 0） |
| --- | --- | --- |
| 回退写口/发版单 | 状态 `回滚中`，返回残留数与缺口；幂等重放不改状态 | 状态 `已回滚`，残留数 0、缺口 0、退役批次行落账 |
| 名册版本 | 保持回退前版本，不提前切 | 同事务切到回退目标版本 |
| 实例册 | 旧包行挂 `residual_release_id` + `retired_by_release_id`，目标版本行在册 | 无该单残留/退役行，册内仅目标版本等在册行 |
| 健康探针 | 可绿可红，不改变残留/退役身份，不改变缺口 | 无残留行可指 |
| 对账 | 不计已回滚；进「回退残留桶」+「回滚缺口桶」；账实口径标「不一致」 | 计已回滚；账实「一致」；`假干净单数` 恒为 0 |
| 总览 | `回滚中` 计数 + 残留露口 + 缺口露口（缺口实例数/已回滚仍有缺口单数） | `已回滚` 计数，缺口露口不含该单 |
| 审计 | 「回滚启动」事件；每次清理写「残留清理」；回执逐条重放校验 | 「回滚收敛完成」事件，重放校验「一致」 |
| 清理入口 | 单行/按发版单批量清理本单缺口行（残留标∪退役标），清理后立即再收敛 | 无缺口可清，调用返回 0 行 |

## 6. 不变量（测试夹具必须全部守住）

1. 不存在 `status='已回滚'` 且该单四源任一缺口 > 0 的发版单（含残留行数 > 0）。
2. 不存在 `status='回滚中'` 而名册版本已等于回退目标版本的发版单。
3. 残留行/退役行的版本必然不等于该单回退目标版本，且与该单同应用同环境。
4. 探针对残留行的任何改灯操作不改变残留行数、退役标与发版单状态。
5. 对账「已回滚」计数 = 发版单表 `已回滚` 行数 = 总览 `已回滚` 计数。
6. 对账残留桶残留总数 = 实例册非空残留标行数 = 总览残留实例数。
7. 对账「回滚缺口桶」缺口明细 = 总览「缺口明细」= 发版详情「回滚缺口」，逐单同值。
8. 回退写口幂等重放后，`发版单状态` 与重放前一致（回滚中不得被洗回已放行）。

## 7. 夹具分套

- 留旧包套：回退后旧包进程仍在（含半截部分切流、并发心跳、残留行绿灯），断言停在
  `回滚中` 且各面残留可核。
- 清干净套：清完残留才允许 `已回滚`（含启动即无残留的即时收敛、单行/批量清理、幂等
  重放），断言收敛事务内名册与状态同时翻转。

金丝雀比例语义与名册真源重构不在本口径范围内，另立。
